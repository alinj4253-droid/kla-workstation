# KLA 知识库模块落地方案

## 1. 目标与范围

知识库按企业、项目、个人三种作用域隔离。客户端负责目录、列表、上传和预览交互；服务端负责权限校验、原始文件保存、标准化、切片、向量化、索引和检索。客户端不得直接访问数据库、Qdrant 或模型服务。

## 2. 信息架构

- 知识库目录：按三种作用域分组展示卡片，卡片显示名称、说明、文件数、切片数、更新时间和处理状态。
- 知识库详情：顶部返回、上传文件、搜索和处理状态；Tab 分为“原始文件”和“知识切片”。
- 原始文件：展示文件名、类型、大小、处理状态和更新时间，支持多文件上传与预览。
- 知识切片：展示标题、来源文件、页码/章节、`startOffset/endOffset`、摘要与详情预览。
- 右侧预览：文本/Markdown 使用正文预览，图片/音频/视频使用媒体控件，Office/PDF 使用服务端生成的安全预览 URL。

## 3. 三层模型与权限

`enterprise` 必须绑定企业身份，企业管理员可创建、修改、删除；`project` 必须绑定项目，创建者拥有管理权，项目成员默认只读；`personal` 绑定当前身份，成员只能管理自己的个人库。所有列表、预览、上传、处理、检索接口都必须按当前身份重新鉴权，不接受前端传入的权限结论。

## 4. 文件生命周期

`uploaded -> processing -> ready`，异常进入 `failed`，用户可重试或取消。只有 knowledge base、source、chunk 均为 `ready` 时才能进入检索索引。新文件在处理期间展示“知识录入中”，不出现在检索结果中。

## 5. 文件处理路由

| 类型 | 路由 |
|---|---|
| pdf/doc/docx/txt/md/html | 文本提取；扫描 PDF 先 OCR，再切片 |
| xls/xlsx | 服务端转 Markdown/CSV，保留工作表与单元格定位，再切片 |
| ppt/pptx | 按幻灯片提取文本、备注和页码，再切片 |
| png/jpg/jpeg | PaddleOCR-VL 输出 Markdown，再切片 |
| mp3/wav/m4a/mp4/mov | Whisper 转写；可选 polish；按时间段切片 |
| mp4 | 以音频转写为主，视频关键帧 OCR 作为扩展能力 |

统一产出标准化正文、切片定位信息、embedding 引用和远程任务 ID。原始文件与标准化文件保留版本关系，重复文件按 SHA-256 去重。

## 6. 服务端数据模型

- `knowledge_bases`: 作用域、身份/企业/项目绑定、名称、说明、状态、创建者。
- `knowledge_sources`: 原始文件元数据、SHA-256、对象存储 key、MIME、处理路线、状态。
- `knowledge_source_versions`: 文件版本和标准化文件引用。
- `knowledge_chunks`: 内容、标题、页码、章节、offset、embedding 引用和状态。
- `knowledge_jobs`: 阶段、进度、错误、远程任务 ID、开始/完成时间。
- `knowledge_previews`: 安全预览 URL、内容类型、过期时间。

建议所有表带 `created_at/updated_at`，并对 `identity_id + scope_type + name`、`knowledge_base_id + sha256` 建索引。

## 7. 前端状态与接口边界

前端维护目录/详情视图、active knowledge base、Tab、上传队列、预览项和任务状态；真实数据通过 `apps/desktop/src/api/client.ts` 调用 KLA 服务端。上传采用 multipart；处理采用轮询或 SSE。服务端未接通前允许使用 mock，但 mock 数据结构必须与 API 契约一致。

## 8. 检索规则

检索请求必须携带当前身份和可访问 knowledge base 范围。默认走 hybrid；明确要求“整份文件/逐条比较/依据某文件”时调用全文读取接口，普通问题走切片检索。任何非 ready 内容不得命中。

## 9. 错误与可观测性

统一返回 `code/message/requestId`；上传失败、格式不支持、权限不足、任务失败、预览过期分别提示。任务日志记录 route、耗时、远程请求 ID、文件 hash 和错误阶段，支持按任务重试且不得重复创建索引。

## 10. 验收标准

覆盖三层知识库权限、一次多文件上传、拖拽/选择文件、全部支持格式、处理进度、失败重试、切片定位、原始文件/切片预览、ready 过滤检索、重复文件去重和跨身份隔离。

## 11. 开发拆分

前端目录与详情页面、上传组件、预览组件、任务状态管理可并行；后端 CRUD/权限、对象存储、文件解析路由、知识服务代理、向量入库、检索和迁移脚本可独立开发，最终以 API 文档和集成测试合并。
