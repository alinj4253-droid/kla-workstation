# 分布式智能体运行时落地说明

## 目标

统筹智能体固定运行在服务端，负责理解用户目标、读取当前群聊角色注册表、生成任务计划并协调多个执行者。其他智能体定义保存在服务端，创建或编辑时可以选择服务端执行或本地设备执行。知识检索、短期记忆、成果读写等服务端技能与本地 read/list/write/code/BAT/CLI 技能统一挂载到技能目录中。

## 运行边界

- 服务端权威保存账号、身份、权限、群聊、消息、智能体定义、技能开关、任务计划、工具调用、运行事件和成果元数据。
- 统筹智能体只能服务端执行，数据库约束禁止把它切换到本地。
- 服务端智能体可以直接调用已有知识与记忆服务；不复制或改造知识库、算力、记忆模块。
- 本地智能体运行时位于 Electron 主进程，通过主动连接服务端（本机预览可用 loopback HTTP，远程部署必须配置 HTTPS）轮询任务，不开放入站端口。工具以当前 Windows 用户权限运行，不自动提权。
- 写入本地文件、保存代码、BAT 和 CLI 在桌面端逐次弹窗审批；技能默认开启不等于静默授权危险操作。浏览器预览不提供本地执行设备。
- 渲染层只调用 REST 和类型化 preload，不接触数据库、文件系统或模型密钥。

## 一次群聊请求

1. `POST /v1/conversations/:id/messages` 写入用户消息并创建 `queued` 运行记录。
2. Loop worker 以 PostgreSQL 租约领取运行。同一群聊按创建顺序串行，不同群聊最多并行处理 3 个运行。
3. 统筹读取角色注册表，闲聊直接回复；单一执行者生成一项委派；复杂任务生成最多 16 项 todo，并用前置步骤编号表达串行/并行依赖。
4. 计划和角色快照事务写入 `conversation_run_steps`。就绪步骤最多并行 4 项；依赖未完成的步骤不会被执行。
5. 服务端技能在 worker 内执行。本地技能写入 `runtime_tool_calls`，由已注册且在线的身份设备领取。
6. Electron 执行器将结果以带 `receiptId` 的回执提交。写文件/代码时校验 SHA-256，并将成果副本写入 `artifacts`；本地绝对路径留在设备，不回传。
7. 单任务执行者直接 `@用户`；多任务执行者向 `@统筹智能体`反馈，所有步骤完成后由统筹汇总一次并把成果编号发给用户。
8. 每个状态变化写入 `runtime_events`，前端通过运行查询和消息刷新展示规划、等待设备、工具执行、完成、失败或取消状态。

## 安全与可靠性

- 每个 API 请求同时验证 Bearer 会话、当前身份和动作权限；跨身份访问在查询层拒绝。
- 设备注册绑定身份、会话和安装 UUID。轮询时锁定设备行，保证一台设备不会同时领取两项工具调用。
- 运行、步骤、工具调用和消息均使用幂等键/唯一约束。设备崩溃后不会自动重做可能产生副作用的调用，而是提交“结果未知”回执并停止该任务。
- 运行拥有 60 秒租约和心跳；取消会同时更新运行、步骤、工具调用并中止 worker 控制器。
- 工具参数经过共享 Zod 合约校验；成果回执接口 body limit 为 4 MiB，单个文本成果仍限制 1 MiB。

## 默认技能

系统为每个身份的非统筹执行智能体挂载并开启以下技能：知识检索、知识全文读取、短期记忆使用、成果文件保存/读取、本地 read、目录查看、write、代码编写、BAT、CLI。设置中心的“技能管理”读取服务端真实开关，任何切换都会持久化；停用技能后，服务端和设备轮询都会拒绝后续调用。

## 桌面执行设备接口

- `POST /v1/runtime/devices`：当前身份注册或刷新设备。
- `POST /v1/runtime/devices/:deviceId/poll`：心跳并领取一项待执行本地调用。
- `POST /v1/runtime/devices/:deviceId/calls/:callId/receipt`：提交完成/失败回执和可选成果副本。
- `DELETE /v1/runtime/devices/:deviceId/connection`：主动断开设备连接。
- `GET /v1/runtime/events?after=...`：按身份读取增量事件。

## 前端入口

设置页的智能体管理使用 `/v1/agents`、设备和模型接口，保存执行位置、设备与模型绑定；技能管理使用 `/v1/skills`。群聊顶部的角色池按钮使用 `/v1/conversations/:id/agents`。运行中的群聊展示当前阶段和等待原因，消息内成果编号可以打开右侧预览或下载。
