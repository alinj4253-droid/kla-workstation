# KLA Workstation 当前功能文档

> 基线版本：当前代码库（2026-09）  
> 文档用途：作为下一版本需求改造、范围确认和验收标准的现状基线。  
> 说明：本文只描述通用产品能力，不包含任何演示群聊、固定演示剧本、演示角色、演示台词或演示材料。

## 1. 产品定位与运行边界

KLA Workstation（鲲擎工作站）是本地优先的 Electron 多智能体协同工作站。它以桌面主进程作为权限、持久化和调度边界，以 React 渲染器提供工作区、群聊和设置界面，以独立 Runtime/Agent 层执行智能体任务。

### 1.1 技术分层

| 层级 | 当前职责 |
| --- | --- |
| Electron 主进程 | IPC、SQLite、文件系统、工作区路径、任务调度、消息落库、知识处理、渠道和外部 CLI |
| Preload 类型化桥 | 向渲染器暴露 `window.kunqing` 能力；隔离 Node/Electron 权限 |
| React 渲染器 | 首页、群聊、工作区、项目、操作、会议、设置、文件预览和消息交互 |
| Agent Runtime/领域包 | 模型网关、Agent 执行、记忆、知识、渠道、数据库和契约 |

运行时保持 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。业务数据和密钥不由渲染器直接写入。

## 2. 工作区与数据分区

工作区根目录默认为 `K_Studio`，可在安装/工作区选择流程中配置。UI 的“个人、项目、企业”是逻辑作用域，实际通过统一路径解析映射到物理目录。

```text
K_Studio/
├── .kstudio/                 # workspace.json、SQLite、锁、日志、缓存
├── group-chats/<id>-workspace/ # 群聊个人作用域（每个群聊隔离）
│   ├── original-files/       # 原始上传文件
│   ├── standardized-files/   # 标准化全文；不参与普通检索
│   ├── knowledge/            # 切片、索引和知识化结果
│   ├── temp/<rootRunId>/     # 单次任务中间产物、证据和版本
│   ├── templates/            # 材料模板
│   └── outputs/              # 已确认的正式成果
├── projects/<projectId>/     # 项目共享作用域
│   ├── original-files/
│   ├── standardized-files/
│   ├── knowledge/
│   ├── templates/
│   └── outputs/
├── shared-knowledge/         # 企业共享作用域
│   ├── original-files/
│   ├── standardized-files/
│   ├── knowledge/
│   ├── templates/
│   └── outputs/
└── meetings/<meetingId>-workspace/ # 会议相关文件和转写
```

### 2.1 文件生命周期

1. 用户上传文件先进入当前作用域的 `original-files`。
2. 知识化流程按需解析/OCR，生成 `standardized-files` 的标准化全文及 manifest，同时生成带 offset、页码、章节定位的知识切片。
3. `standardized-files` 是整文/分段读取的规范化来源，不参与二次知识化和普通 RAG 检索。
4. `temp/<rootRunId>` 仅保存当前任务的框架、检索证据、候选稿和版本，不参与知识化和普通检索。
5. 只有系统确认文件真实存在、内容可读且符合交付条件后，才允许从临时成果提升到 `outputs`。
6. 文件跨作用域发布时支持基于内容哈希复用标准化/知识化结果，避免重复处理。

当前工作区页面支持目录浏览、上传、建文件夹、重命名、删除/回收、文件预览、系统打开、知识化和个人文件发布到关联项目。群聊可在个人、关联项目和企业工作区之间切换；默认输出在个人作用域。

## 3. 首页、群组与群聊

### 3.1 首页

- 从输入框提交需求并创建新的协作群组。
- 支持附件上传、图片和 `@智能体` 输入。
- 支持快速、均衡、专家三档协同模式。
- GM 依据完整用户需求和可用角色池选择最小智能体团队、生成群组名称，并确保统筹智能体加入。
- 首页提供推荐多智能体项目入口；具体成员以当前配置和可用外接 CLI 为准。

### 3.2 群组列表和群聊

- 群组二级列表持久化显示名称、头像缩写、关联项目和最近回复时间，并按最近消息倒序排列。
- 支持新建群组、成员管理、操作智能体挂载、项目关联和群聊更多操作。
- 群聊消息支持文本、Markdown、文件、图片、音频、视频和链接；消息中可显示发送者头像、昵称、@高亮、引用消息和流式状态。
- 支持右键回复消息。引用内容在输入区上方展示，过长时截断，避免横向滚动；用户回复带引用时关联原工作树，普通消息默认创建新工作树。
- 用户发送后会先写入并显示自己的消息，再触发后续智能体执行；滚动位置不在底部时会自动将视图带到新发送内容。
- 顶部通知铃铛在用户未读到智能体消息时显示红点，通知按时间倒序展示。
- 智能体消息和文件发送具有消息幂等与去重处理，避免同一结果重复落库或重复展示。
- 群聊支持右侧工作树、任务计划、任务节点、执行状态和成果引用；任务执行不会因用户切换到其他页面而停止。

## 4. 智能体体系与协同调度

### 4.1 角色注册

创建群聊及成员变更时，系统将成员的公开职责、角色、运行方式、操作平台和生效技能编译为群聊级 `project_agent_coordination` 注册表。注册表包含统筹自身，是统筹选择成员的集中能力索引；角色卡源文件仍是可编辑事实源。

当前通用成员包括：

| 角色 | 当前职责 |
| --- | --- |
| 统筹管理智能体 | 还原用户目标，判断简单/复杂/缺少输入，按能力注册表委派和汇总 |
| 本地执行智能体 | 在自身 loop 内按需完成知识化、内部/外部检索、整文读取、模板编写、成果验收和真实文件交付 |
| 操作智能体 | 只处理绑定操作平台上的网页任务和已生效操作技能 |
| 会议智能体 | 处理会议录音/实时语音、转写、说话人确认、摘要、纪要和待办 |
| Kimi Code | 外接 CLI 代码编写智能体（需检测到并完成接入） |
| CodeBuddy | 外接 CLI 验收智能体（需检测到并完成接入） |
| 自定义智能体 | 用户创建的角色、模型、技能和权限组合 |

知识管理、资料调研、材料编写和验收的历史独立定义仅保留兼容记录；新群聊中其能力作为本地执行智能体的技能挂载，不再作为统筹应默认拆出的独立成员。

### 4.2 统筹调度规则

1. 简单闲聊、时间天气和无需工具的轻量问题由统筹直接回答。
2. 单一专业能力可完成的任务，统筹只向匹配成员发送一次简洁 query，被委派成员直接返回用户可读结果。
3. 复杂任务由统筹形成业务结果导向的 TODO/DAG，记录依赖、负责人、串并行方式、完成标准、状态、结果消息和成果引用。
4. 有依赖时等待上游真实结果；仅在互不依赖且有明确收益时并行。
5. 子任务完成后由被委派成员明确反馈给统筹；用户需要提供关键结果时进入 `waiting-user`，不因普通 `@用户` 自动阻塞。
6. 任务完成前不重复提问、不重复委派；消息路由使用原工作树和触发消息关联用户回复、委派反馈和等待状态。
7. 统筹不把本地执行智能体的内部技能再次拆成知识、调研、编写、验收四个外部步骤。

### 4.3 协同模式

| 模式 | 当前预算和行为 |
| --- | --- |
| 快速 | `thinking=false`、`thinkingLevel=none`；只做必要动作；网页/知识检索合计最多 1 次；不创建分身、不做独立验收 |
| 均衡 | `thinking=minimal`；网页/知识检索合计最多 3 次；分身、重试共享额度；整棵任务树最多一次验收 |
| 专家 | 保留完整思考和关键核验；网页/知识检索合计最多 8 次；按风险决定分身、复核和返修 |

检索、工具、重试和分身均受当前根任务预算限制，不应由单个成员无限循环。

## 5. 本地执行智能体及技能

本地执行智能体是当前本地资料和成果类任务的闭环执行者。它接收完整业务工作包，在自身 loop 内按需选择以下技能：

- **知识管理技能**：OCR、解析、标准化全文、切片、向量/图谱/Wiki 投影、来源状态维护。
- **知识检索与整文读取技能**：在个人、关联项目和企业三层作用域检索；明确点名文件、依据文件、全文审阅或逐条比较时连续读取标准化全文。
- **资料调研技能**：博查等外部搜索、来源核验、事实综合；按模式共享搜索预算。
- **材料编写技能**：读取模板、复用 HTML 外壳/CSS/logo/页眉页脚/背景，按证据生成报告、方案和 HTML 等成果。
- **验收技能**：按需求、模板、来源和证据核验成果，给出通过/返修结论；快速模式不启动独立验收。
- **分身代理技能**：仅在均衡/专家模式且存在独立子任务时并行执行，主任务必须等待并汇总分身结果。

本地执行智能体的正式回复只输出用户可直接阅读的结论、关键证据、风险和真实成果，不输出内部思考、工具调用、JSON、工作包或旧专业角色名。

## 6. 操作平台与操作技能

操作模块用于绑定网站并创建专属操作智能体。

- 创建操作平台时填写平台名称、URL、平台描述、操作智能体名称和必选模型。
- 平台监控页包含网页嵌入、操作智能体对话、历史/对话切换和已挂载技能卡片；支持网页前进/后退。
- 创建技能时录制网页操作并保存视频，同时收集 DOM 事件/元素轨迹和用户文本说明。
- 技能学习阶段将用户行为与 DOM 穿透事件归并为业务工作流节点，并结合截图/视觉校验；不确定的业务含义才向用户提问。
- 技能生效前处于草稿/学习状态；修改已生效技能会生成待生效业务工作流，点击“生效技能”后替换执行版本。
- 技能管理支持启用/停用、查看录制视频、业务工作流、DOM 映射和修正对话；删除需要二次确认。删除操作平台时相关技能注销而非物理删除。
- 技能调用时由操作智能体根据用户目标选择技能、执行 DOM/视觉步骤、在重要页面跳转节点做确认，并读取页面结果后返回业务答案。
- 操作智能体加入群聊后会生成角色卡，统筹可按平台职责向其委派；操作页原有交互与群聊协作链路分离。

## 7. 会议

- 左侧会议列表默认不选中已有会议；可从空状态或列表 `+` 创建。
- 创建会议填写名称、可选简介、记录方式（上传录音/实时语音）和关联项目。
- 实时语音创建前检查麦克风、听筒和授权；上传录音不依赖硬件检查。
- 会议页包含“会议语音转写”和“会议纪要”等视图，支持实时/非实时转写、说话人聚类和身份确认。
- 会议智能体结合项目人员、转写内容和用户确认生成摘要、结论、待办；确认信息写入项目共享知识。
- 会议纪要可导出 HTML；会议相关文件保存在会议工作区，并可关联项目。

## 8. 项目管理

- 项目菜单支持创建企业项目、项目列表和项目关联节点。
- 项目详情支持项目名称、详情说明、负责人/关联人员、关联智能体、成本、完成节点等信息。
- 项目看板提供 BI 指标、趋势、完成率、任务状态和成员负载视图；当前部分指标仍为页面 mock 数据。
- 项目进度以任务列表 + 甘特图为主要视图，下方提供完成占比、趋势等仪表盘；当前计划数据为页面 mock 数据。
- 关联节点汇总挂载到项目的群聊、操作平台和会议节点。
- 项目工作区与群聊/操作/会议通过关联关系共享权限和知识范围；群聊或操作的“更多”中可关联项目。

## 9. 设置与平台管理

### 9.1 模型管理

统一模型页面维护模型名称、模型 ID、类型、Base URL、API Key 和模型能力参数。支持官方 CME Cloud DeepSeek V4 Flash、GLM 5.3 Flash 预置模型，以及 DeepSeek、GLM、Kimi、Qwen、GPT/OpenAI、Claude/Anthropic 和 OpenAI 兼容类型。模型卡片支持测试、编辑和删除（官方模型受保护）。

官方模型共用全局 Token 配额，新安装默认 300 万 Token，默认槽位使用 DeepSeek；模型密钥由主进程安全存储，不暴露给渲染器。

### 9.2 智能体管理

页面分为“全部、官方内置、外接三方、自定义”。智能体卡片可挂载模型、管理技能、配置权限；外接 CLI 支持检测和接入向导。当前代码可识别 Codex、Claude Code、Kimi Code、CodeBuddy 等外接适配器，外部 CLI 是否可用取决于本机可执行文件和连接状态。

WorkBuddy/MCP 集成目前在产品界面中隐藏，相关实验性中继和兼容模块保留但不进入默认群聊执行链路。

### 9.3 技能、工具和渠道

- 技能页面展示内置工具/技能及启用状态。
- 渠道页面支持 Telegram、飞书（Lark）、钉钉和企业微信 Webhook 的配置、测试、启停、健康状态和会话绑定。
- 渠道事件具有外部事件去重、限流、重连和会话到项目绑定能力；真实外部服务仍需有效凭据和网络环境，部分本地测试为 schema/mock 验证。

### 9.4 个人、外观、权益和运维

- 个人页可设置昵称和圆形头像；昵称和头像同步到群聊消息、@用户和左下角入口。
- 外观支持标准、专业、科技、尊贵等主题，当前默认专业主题。
- SaaS 模式显示 Token 剩余/总量；私有化模式显示剩余天数/总天数。权益耗尽后进入锁定页，输入运维密钥后仅可进入运维管理，重新配置权益后恢复。
- 帮助按钮打开产品说明文档 PDF 预览。
- 桌面预览可通过仓库根目录的 `启动桌面预览.bat` 启动当前源码版本。

## 10. 文件预览与交付约束

- HTML、Markdown、PDF、Office、图片、音视频和常见文本均通过工作区预览/系统打开能力处理；HTML 可在右侧预览，较大的受信任 HTML 有专门的预览放行边界。
- 群聊附件消息与工作区文件保持文件 ID/相对路径关联，避免只发送虚拟路径。
- 输出文件必须由系统工具真实写入当前任务临时目录，并在确认后提升到当前作用域 `outputs`；消息只引用真实存在的成果文件。
- 模板任务优先从个人、项目、企业模板目录查找并完整读取模板；有匹配模板时保留模板视觉外壳和结构。

## 11. 当前实现边界与下一版需求入口

以下事项是下一版需求梳理时需要单独确认的边界，而非本文默认承诺为已完成能力：

1. 项目看板和项目进度中的部分指标、任务和趋势仍是 renderer mock 数据，需要明确后端数据模型与实时刷新策略。
2. 真实飞书、Telegram、钉钉和企业微信的生产级鉴权、回调公网部署和异常恢复需要按渠道分别验收。
3. 外接 CLI 的检测、连接和运行依赖用户本机安装、权限和 PATH；应补充版本兼容、超时、取消和凭据诊断。
4. 操作技能的 DOM/视觉混合执行受目标网站登录态、跨域策略、元素动态变化和验证码影响，应继续完善回放证据、重定位和人工接管。
5. 会议声纹识别、实时转写质量和项目人员自动关联仍需真实音频数据验收。
6. WorkBuddy MCP 当前为隐藏的实验性兼容能力，不应作为默认可用的外接智能体能力对外承诺。
7. 旧智能体 definition、旧适配器和旧工作区目录承担迁移兼容职责，不能在下一版清理时直接删除；应制定迁移完成条件。

## 12. 下一版需求文档建议结构

建议后续每个需求按以下结构编写：

1. 用户目标与适用作用域（个人/项目/企业/群聊/操作/会议）。
2. 当前基线和不变范围。
3. 数据模型、文件生命周期和权限边界。
4. Agent 角色、技能、工具和调度节点。
5. UI 状态、错误、等待、取消和恢复行为。
6. 外部依赖与凭据要求。
7. 真实数据、mock 数据和迁移策略。
8. 验收用例、性能预算、幂等/去重和回归范围。
