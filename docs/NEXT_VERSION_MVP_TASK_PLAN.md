# KLA Workstation 下一版本 MVP 任务计划

> 来源：`NEXT_VERSION_MVP_REQUIREMENTS.md`、`NEXT_VERSION_MVP_TECHNICAL_DESIGN.md`
> 用途：开发排期、责任分工、依赖管理和版本验收。
> 状态约定：`未开始`、`进行中`、`阻塞`、`已完成`。

## 一、任务总览

| 阶段 | 目标 | 前置条件 | 主要交付物 |
|---|---|---|---|
| P0 方案与基础设施 | 确认部署、数据和安全边界 | 无 | 部署方案、环境、基础工程 |
| P1 算力与模型服务 | 提供统一模型和多媒体算力 | P0 | OCR、Embedding、Whisper、sub2api |
| P2 服务端基础 | 建立身份、权限、存储和任务底座 | P0 | API Gateway、数据库、对象存储、队列 |
| P3 知识服务 | 完成服务端知识处理与检索 | P1、P2 | 文件、解析、切片、向量化、检索 API |
| P4 记忆与成果 | 完成长期记忆和服务端文件成果 | P2、P3 | Memory/Artifact Service |
| P5 桌面端接入 | 完成客户端服务端化和新页面 | P2、P3、P4 | Main/Preload/Renderer 联调 |
| P6 智能体生态 | 扩充智能体、技能和 MCP | P2、P5 | 文档编写、PPT、数据分析智能体 |
| P7 数据迁移 | 迁移现有本地工作区 | P3、P4、P5 | 迁移工具、兼容和回滚 |
| P8 集成验收 | 验证端到端稳定性和安全性 | P1-P7 | 测试报告、发布候选版本 |

## 十一、建议并行关系

- P1-02、P1-03、P1-04 可在算力环境就绪后并行部署。
- P2-01 至 P2-06 可在基础数据模型确定后并行开发，但 P2-03 权限服务应先于业务 API 完成。
- P3-02、P3-03、P3-04 可按解析器类型并行开发；P3-05、P3-06 依赖标准化文本契约。
- P5-04、P5-05、P5-06、P5-08 可并行开发，统一依赖服务端 API 契约。
- P6-03、P6-04 可并行开发，统一复用文档、成果和用量服务。
- P7 数据迁移必须在服务端知识闭环通过后开始正式迁移。
