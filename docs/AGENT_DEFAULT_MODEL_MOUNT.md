# 智能体默认 Key 与模型挂载

## 默认行为

每个账号身份独立使用自己的「默认工作站 Key」。该身份下的官方智能体（统筹智能体、本地执行智能体、PPT 助手）和新建智能体，首次初始化时自动挂载该 Key 与 **GLM 5.3 Flash**，模型 ID 为 `zhipu/glm-5.3-flash`。

个人、企业管理员、企业成员身份分别初始化，切换身份不会复用其他身份的 Key。用户可在「智能体 / 我的智能体 / 挂载模型」切换当前身份下的 Key，并选择该 Key 实际可用的模型。

## 初始化与异步建号

身份创建后的算力建号仍走现有 Outbox 流程。默认 Key 尚未创建时，智能体可以先创建，挂载保持待初始化；Key 落库后自动补齐。智能体注册表加载也会检查未初始化记录，覆盖「先创建 Key」和「先创建智能体」两种顺序。页面对待初始化状态每五秒刷新一次。

初始化使用 `agents.model_mount_initialized` 标记。自动挂载只有首次生效，重复加载不会增加智能体版本，也不会覆盖用户手动选择的 Key、模型或主动取消挂载。自动绑定只选择同身份、默认、启用且未过期的 Key，并要求模型存在于启用的服务端目录；实际调用仍由算力网关检查上游凭据、可用模型和余额。

## API 语义与升级

- `POST /api/v1/agents` 未提供模型/Key，或两者均为 `null`：自动使用身份默认配置；Key 未就绪时稍后补齐。
- `POST /api/v1/agents` 显式指定模型与 Key：按用户配置保存，沿用已有的身份与上游可用模型校验。
- `PATCH /api/v1/agents/:agentId` 显式修改模型或 Key：标记为用户配置，后续初始化不覆盖；两者均为 `null` 表示主动取消挂载。
- `PATCH` 仅修改名称、职责等字段：保持原挂载初始化状态。
- `GET /api/v1/agents` 和工作站 Bootstrap 返回 `modelMountInitialized`，供前端展示等待状态。

部署时运行 `pnpm --filter @kla-workstation/server db:migrate`；服务端启动也会执行现有迁移检查。迁移 `0043_agent_default_model_mount.sql` 为已有未完整挂载的智能体补齐本身份默认 Key，已有模型选择保留，已有完整绑定保持不变。没有可用默认 Key 的记录保持待初始化。

群聊编排、执行和总结继续使用持久化的 `model_id` 与 `model_key_id` 进入现有算力网关，前端不接触上游 Key 明文。
