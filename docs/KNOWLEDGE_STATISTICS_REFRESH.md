# 知识库统计刷新修复

更新日期：2026-10-08。

## 原因与修复

1. 总览、详情切片列表和检索来源采用不同的切片缓存键；部分请求失败后不再更新。改为共享 `useKnowledgeSlices`，以服务、集合、文档 ID、修改时间、大小和 stale 状态区分缓存。失败/待处理来源自动再次读取，正常来源每 30 秒更新。
2. 详情统计依赖已挂载的切片 Tab。现在统计卡独立读取经过契约校验的切片，留在“原始文件”Tab 也更新。
3. “刷新任务”只更新文件与任务，没有更新切片内容。现在刷新当前服务、集合下的任务、来源、绑定和切片缓存；任务结束时立即刷新该来源内容和绑定。
4. 收到 SSE 初始消息后停止轮询，静默丢失后续消息时停在旧状态。现在运行中的任务持续按连接配置轮询，同时接收即时 SSE 更新；确定不存在或无权限等不可重试错误停止轮询。
5. 单个来源未关联任务就让全部状态统计显示“—”。现在按可确认状态分别统计，未关联任务但已有有效切片且原件未过期的文件计入已处理，无法确认的文件明确注明数量；不把未知状态计为失败或处理中。
6. 单任务变化立即同步到任务历史缓存，便于总览处理状态一并更新；旧快照仍不能覆盖较新的终态。
7. 上传返回真实绑定后刷新当前集合缓存。切片 404 明确提示“尚未生成切片”，定时重试，不将不可用切片当作零。

8. 任务完成时尚未取得原件 docId，后续关联到原件后也触发内容刷新；避免因为终态没有再次变化而漏掉这次更新。

## 合并 B 模块后的复核

本地修复与远端 B 的独立阅读、切片和检索模块合并后，统计统一调用 B 的类型化 `slicesOptions` 与 `fetchDocumentSlices`，使用 `readingContext/sourceResourceVersion` 生成同一缓存键。手动刷新同时刷新 A 的集合缓存和 B 的 reading 缓存；任务结束按 B 的来源切片缓存前缀更新。保留 B 的来源校验、抽屉定位和焦点恢复，也保留本地任务记录删除和知识库菜单。

合并后全项目类型检查、A/B 相关代码 ESLint、现有统计刷新回归 12/12 以及 Main/Preload/Renderer 编译均通过。上节 18 项是合并前记录；远端移除了旧 A completion-audit 用例，未将该旧用例数当作合并后重跑结果。旧阅读面板与 read-model 按 B 的接入方案移除，统计和回归夹具已适配 B 的 DTO 与错误类型。

## 范围

不修改服务器服务或数据，不猜测任务编号，不写入知识库内容。删除任务记录仍仅移除本机历史显示；来源绑定、文件状态和统计保留。
