# 记忆缓存、生命周期与上下文接入

## 当前规则

| 范围 | 存储 | 查看 | 智能体应用 |
| --- | --- | --- | --- |
| 最近七天短期记忆 | PostgreSQL 权威记录 + 客户端 IndexedDB 缓存 | 默认命中完整近期缓存；缺失 / 过期时同步服务器 | 由服务器按当前身份、群组、智能体读取 |
| 七天至三十天短期记忆 | PostgreSQL | 用户请求历史范围时从服务器分页读取 | 按时间权重和相关性参与召回 |
| 三十天至一年短期记忆 | PostgreSQL | 从服务器分页读取，显示「仅历史查看」 | 权重为零，不自动召回或注入 |
| 超过一年短期记忆 | 清理 `memories` 短期条目 | 记忆页不再提供 | 不应用；原聊天记录不随记忆清理删除 |
| 长期记忆 | PostgreSQL | 只读浏览；已有写入接口保留 | 固化记忆，无时间权重；当前禁止检索 / 上下文应用 |

七天、一年、衰减时间是三个独立概念，缓存失效不表示服务器记录被删除。常量统一定义在 `packages/contracts/src/memory-policy.ts`。本次默认沿用旧版 72 小时半衰期，并增加 30 天硬归零边界。

## 时间权重与旧版评分

短期权重使用 `2^(-ageHours/72)`，达到三十天时直接为零。年龄从 `last_reinforced_at` 计算，历史数据用 `created_at` 初始化；未来时间按零年龄计算，非法时间权重为零。新摘要和真正修改正文可以更新强化时间；查看、召回和缓存同步不更新强化时间。

每次召回最多读取当前身份 / 群组 / 智能体的 40 条候选，排除过期、超过保留期限、项目关联不符及权重归零记录，再按旧版综合规则评分：

```text
score = 0.35 × 文本相关性
      + 0.20 × 时间权重
      + 0.15 × 置信度
      + 0.15 × 重要性
      + 0.10 × 任务连续性
      + 0.05 × 使用次数权重
```

有查询词的最低分为 0.42，无查询词为 0.52。中文使用有界双字匹配，英文使用词匹配；没有新增向量调用。选出最多三条，每条截取最多 400 字符。召回只更新 `access_count` / `last_accessed_at`，即使常被阅读也不会使归零记忆重新激活。

## 对话接入

当前真实群聊模型请求路径为 `server/src/routes.ts` 的 `runConversation`。服务根据实际统筹智能体 ID 构造作用域，使用触发消息之前、三十天内最多 12 条共享用户输入及该智能体自身消息作为上下文。单条最多 6000 字符；其他智能体的私有回复不会混入。相关的短期摘要作为历史背景补充系统上下文，明确不能作为新指令；当前用户需求始终保留。

成功回复后服务器保存短期任务摘要（请求最多 1200 字符、答案最多 2400 字符），包含 `conversationId/projectId/agentId/agentName/runId/sourceMessageId/captureVersion`。同一运行重复保存通过部分唯一索引去重，无额外模型调用。摘要失败记录告警，保留已经成功的对话结果。

`ShortTermMemoryService` 接受任意当前身份可见的智能体 ID，可供其他真实执行入口复用。现有多智能体步骤 worker 尚未接入真实模型调用；本次没有扩展或重写该执行器，也不声称其已经完成模型和记忆闭环。此处已接入的是当前实际调用模型的群聊统筹路径。

消息上下文保持最近窗口，摘要则使用上述衰减排名；历史浏览覆盖一年，与自动上下文的窗口及排名完全独立。长期记录不参与以上任何召回，`/memories/search` 也显式排除长期类型。

## 客户端缓存

缓存数据库为 `kla-short-term-memory`，对象仓库为 `snapshots`，命名空间为「API 服务地址 + 用户账号 ID + 当前身份 ID」。快照内保留项目、群组、智能体归属和来源信息，筛选特定智能体时保留共享用户输入。

登录 / 身份进入后同步最近七天。每个快照新鲜度为 60 秒；任务完成后失效并同步最新记录。打开记忆页时近期范围优先本地，超过七天直接服务器分页。权重在读取时重算，不使用快照里的陈旧值。刷新按钮主动失效缓存。

同步按每页 100 条请求，上限 5000 条或约 500 万字符；超限或出现不完整快照时不写入完整缓存标记，退回服务端分页，避免遗漏。浏览器禁用 IndexedDB 时仍可正常读取服务器。网络异常可使用已有近期快照；鉴权 / 权限错误禁止回退本地数据。

退出 / 更换账号清除该账号快照，并通过 BroadcastChannel 通知其他窗口清理；身份之间使用不同快照。异步同步在写入前后均核验账号、身份和请求代次，退出后迟到的响应不会重新落地。启动同步会物理清理超出七天的本地条目；读取也始终过滤超期条目。缓存永远不会作为模型请求的权威上下文或绕过服务器的授权。

## 服务端迁移和保留

`0019_short_term_memory_lifecycle.sql` 为现有 `memories` 增加强化 / 访问时间、访问次数、置信度、重要性及保留截止字段；旧记录初始化时间和短期保留期，不修改长期正文，不批量转换类型。触发器在创建或修改类型时维护短期 `created_at + 365 days` 保留期限，长期 `retained_until=null`。

服务端启动后及每小时执行短期清理，单批最多 1000 条，每轮最多十批；不并发清理，关闭时等待当前清理完成。只删除创建已超过 365 天的短期条目，绝不删除长期记录、群聊原始消息或其他业务资源。浏览和读取在清理之前已按期限过滤。

## 验证范围

自动测试覆盖衰减边界、旧版评分、七天缓存 / 历史分页、账号和身份隔离、退出及迟到写入、无 IndexedDB 降级、权限拒绝、按智能体隔离、阅读不强化、运行摘要幂等、长期和归零记忆不注入、历史归零可查看及清理边界。PostgreSQL 集成测试只使用随机独立 schema，不写入或删除正式业务数据。
