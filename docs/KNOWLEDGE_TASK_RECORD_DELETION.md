# 上传处理任务记录删除

更新日期：2026-10-08。

## 使用方式

- 已完成、失败、取消、中断的任务行显示“删除记录”。
- 点击后显示确认弹窗，取消会保留记录。
- 确认成功后，该任务从本机“上传处理任务”列表移除；刷新、重新进入页面和重启应用后仍保持移除。
- 排队或运行中的任务不能删除。确认时 Main 会通过 `GET /v1/jobs/{id}` 再核对真实状态，拒绝删除仍在处理的记录。
- 删除失败时弹窗保留并显示错误，任务行不会提前消失。

## 接口和保存方式

新增 `knowledgeLibrary.deleteJobRecord({ serviceInstanceId, jobId })`，通过类型化 Preload 调用 Main；返回带 `taskRecordDeletedAt` 的原始来源绑定。

服务当前没有任务记录删除接口。本功能仅清理本机可见的任务历史，不删除服务器任务、原始文件或知识切片。Main 在 `bindings.json` 中保存删除标记并保留来源与任务的对应关系，所以文件显示名称、处理状态、来源权限和统计不受删除操作影响。写入采用现有原子保存与串行队列；旧数据没有删除标记时照常显示。

删除入口只操作当前服务、集合和凭证上下文中已绑定的任务，拒绝任意未绑定任务编号。确认弹窗说明本机删除范围。

## 手动验收场景（本次未执行）

1. 删除已完成任务：列表行消失，原始文件仍显示原名称与已完成状态，统计保持不变。
2. 删除失败、取消、中断任务：删除成功且其他任务、重新上传入口不受影响。
3. 在确认弹窗取消：记录保留；处理中的任务不出现删除入口。
4. 刷新、离开并返回、重启：已删除的记录不再出现。
5. 服务断网、拒绝访问或本机保存失败：保留记录并显示错误，可重试。
6. 旧状态显示为已结束但服务实际仍在运行：Main 拒绝删除。
7. 删除与刷新同时发生：迟到的缓存结果不能让当前页面的已删除行重新出现。
8. 切换服务或集合：不能删除其他上下文中的记录。
