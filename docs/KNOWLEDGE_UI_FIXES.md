# 知识库 UI 修正（2026-10-08）

## 统计卡
- 原始文件列表成功后，已处理、处理中、异常显示已确认的数量（包括 0），不再因为全部文件状态未知而一起显示破折号。
- 待确认文件数量单独标注；此时数字仅代表已确认的文件，不代表未知文件没有处理中或异常情况。
- 任务查询成功时以任务状态为准；历史任务查询失败或无记录时，非过期、校验通过且非空的切片可确认文件已处理。
- 原始文件列表未获取成功时仍显示未知，避免把请求失败写成 0。
- 截图中的“已关联且状态可用的原件”已不在当前源代码中，运行旧客户端时需关闭并重新启动当前项目。

## 切片查看
- 切片表新增操作列，每条记录提供“查看”，打开当前切片详情。
- 保留标题打开入口；按钮带独立可访问名称并沿用抽屉焦点恢复。
- 调用既有 GET /v1/documents/{doc_id}/slices；查看已读取的切片不额外请求接口。

## 原始文件正文分页
- 调用既有 GET /v1/documents/{doc_id}/content?para=0&limit=2。
- 每次按接口游标读取两段，再按最多 900 个 Unicode 字符或 18 个换行拆成阅读短页；翻页复用缓存，后续内容按需请求。
- 每次只展示当前页；固定高度阅读区域，正文上方有可见的上一页与下一页。未读取完全文时显示已加载页数，全部读取后显示总页数。
- 下一页失败保留当前页，提供重试；切换文件、服务范围或资源版本后回到第一页，并隔离迟到响应。
- 服务端按空行分段，因此阅读页码不对应原始文件物理页码；短文件只有一页。

## 实际接口核对
对 192.168.10.206:8120 只读请求：
- 01-战略锚定韧性生长-李子飞【2026年会】.txt：
  - para=0, limit=2 → returned=2, total_paragraphs=4, next_para=2, has_more=true。
  - para=2, limit=2 → returned=2, total_paragraphs=4, next_para=null, has_more=false。
- 温总视频.txt：首请求 total_paragraphs=9, next_para=2, has_more=true。
- 结论：正文接口支持分页，原页面默认取 20 段并追加展示，造成这些文档没有翻页入口。
