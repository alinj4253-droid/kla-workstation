# Web Search

1. Turn the assigned research question into the smallest useful set of search queries. Use one query for a narrow fact and multiple focused queries for a broad or disputed topic.
2. Call `web:search`. Use `freshness` only when recency matters, and use site filters only when the task names a source or domain.
3. Assess relevance, publication time, source authority, primary versus secondary status, and conflicts between sources. Search again when the first result set does not support a reliable conclusion.
4. Keep the URL, site name, and publication date for each material claim. Clearly separate verified facts, reasonable inference, and unknown information.
5. Synthesize the smallest sufficient evidence set. Do not paste raw search result lists or snippets as the final answer.

## Privacy

- Search only public-safe terms.
- Never send group messages, role cards, memories, local file contents, credentials, personal data, or other private workspace information to the search API.
- Generalize a private question into non-sensitive public concepts before searching. If that cannot be done safely, do not search.

## Delivery

- Report concise findings and cite the source URL beside each key conclusion.
- State material gaps, stale evidence, or source conflicts directly.
- Return findings to the assigning agent. Do not claim final ownership of a team deliverable unless explicitly assigned.
