# STORY.md 撰写规范

> STORY.md 是**叙事契约**：定受众、定目标、定分章、定每页讲什么。写完不改。
> 模板见 `assets/STORY.template.md`。

## 四节结构

### ① 用户意图对齐

必须写清五件事：

| 项 | 要求 |
|---|---|
| **目标受众** | 具体到"懂不懂行"的程度（例：懂行的玩家 / 非玩家的大众），并说明这决定了什么（哪些术语要解释、哪些可直接用） |
| **核心目标** | 讲完之后听众**记住哪 3 件事**。逐条写成一句话 |
| **PPT 长度** | 总页数 + Hero 页配额（Hero 不少于总页数的 20%） |
| **视觉调性** | 用 **5 个词**锁定（例：夜色、霓虹、电影感、潮流、有冲击力） |
| **内容边界** | 三档：**必讲** / **不讲** / **禁碰**（版权、敏感、超纲的都写这里） |

### ② 页面布局骨架

必须包含：

- **页面总数与分章**：每章含哪几页（扉页 + 内容页编号）
- **目录↔章节扉页契约**：一张表把目录条目 ↔ 扉页页码 ↔ 编号一一对应，
  并写明"全篇有且仅有 N 个 `type: section` 扉页"。**这是硬契约，逐字一致。**
- **Hero 页定位**：列出是哪几页、占比多少、两两之间的间隔是否 ≥1 个 supporting 页
- **rhythm 曲线**：逐页标 `peak / transition / valley`，检查**无连续 ≥3 页 valley**
- **版式预算**：非对称版式占比（目标 ≥40%）；对称版式页是否两两不相邻

### ③ 页面大纲（核心表）

逐页一行，列固定：

```
| # | title | type | role | rhythm | layout | visual | visual_role | density | anti_pattern | description |
```

- `type`：`cover` / `catalog` / `section` / `content` / `ending`
- `role`：`hero` / `supporting` / `transition`
- `rhythm`：`peak` / `transition` / `valley`
- `visual`：主视觉文件与占位（如"L1: xxx.png（占 B 区上方 58%）"）
- `visual_role`：`atmosphere` / `anchor` / `evidence`
- `density`：`字数约 N / 图表 N 个 / 留白约 N%`
- `anti_pattern`：**这一页明确禁止出现什么**（防后面写作跑偏）
- `description`：本页要讲的完整内容 + 一条**判断句**（结论，不是事实罗列）

> **"数据 + 判断"两段式**：含关键数据的页，不能只摆数字，必须给出一句判断。
> 例：「2.65 亿美元开发投入」→ 判断：这不是营销预算堆出来的，是把整个世代的技术押注在一张地图上。

### ④ Checklist 自检

把下面这些逐条勾掉（这是 STORY.md 自己的门禁）：

- Hero 页数 / 总页数 ∈ [20%, 30%]
- 无连续 ≥3 页 supporting + valley
- 未使用"等宽卡片横排"这类反模式
- 非对称版式占比 ≥ 40%
- 相邻两页版式均不相同
- 每页均含 role / rhythm / visual_role / anti_pattern
- 含数据的页均按"数据 + 判断"两段式
- `type: section` 扉页数 = 目录声明章节数，编号连续、标题逐字一致

## 写作要点

1. **先定叙事弧，再排页**。16 页不是 16 个独立信息块，要有一条推进线
   （例：起源 → 介绍 → 特色 → 遗产）。
2. **反模式库要具体**。写"禁止把三个卖点做成等宽四卡"，不要写"注意排版美观"。
3. **description 直接可抄成正文**。写得足够完整，写 slides 时几乎不用再构思。
4. 目录每条 ≥ 20 字内容提示，不能只写两个字的标题。
