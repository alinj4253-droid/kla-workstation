# 整体流程（九阶段）

## 总览

```
┌─ 决定层（产出"决定"，不是文件）────────────────────────┐
│ 1 需求对齐    风格 / 用途 / 受众（一次问清，给选项）      │
│ 2 事实核对    联网查证：时间、数据、版本、机制            │
│ 3 锁叙事线    → STORY.md                                │
│ 4 锁设计规范  → DESIGN.md                                │
└──────────────────────────────────────────────────────┘
┌─ 生产层（产出"文件"）────────────────────────────────┐
│ 5 生成主视觉   ImageGen，统一风格后缀词                  │
│ 6 素材加工    裁水印 / 切图 → assets/                    │
│ 7 页面构建    写 slides/NN.slide（页级声明式）           │
│ 8 校验写入    lint 门禁 → upsert-dsl（逐页内循环）       │
│ 9 交付        present_files 打开成品                     │
└──────────────────────────────────────────────────────┘
```

前四阶段产出的是**决定**：风格定调、事实基线、叙事结构、设计常量。
后面所有素材和版式都严格照 `STORY.md` + `DESIGN.md` 执行，**中途不即兴改风格**。

---

## 阶段 1 · 需求对齐

一次性问清三件事，不要零散追问：

| 问什么 | 形式 | 为什么要问 |
|---|---|---|
| 视觉风格 | 给 4 个方向选 1（附预览） | 它决定后续全部色值/字体选择 |
| 用途场景 | 现场分享 / 课程课件 / 阅读存档 | 决定信息密度与文案长度 |
| 目标受众 | 玩家 / 大众 / 学生 等 | 决定术语深度与铺垫量 |

可先用一个内联矢量图渲染出几套配色预览卡，再让用户选——比纯文字描述高效。

## 阶段 2 · 事实核对

联网查证会写进 PPT 的所有硬事实：时间、数字、版本、机制名称。
**不要凭记忆写数据**。核对结果直接进 STORY.md 的内容边界。

## 阶段 3 · 锁叙事线 → STORY.md

四节结构（模板见 `assets/STORY.template.md`）：

1. **用户意图对齐** — 受众、核心目标（讲完记住哪 3 件事）、长度、视觉调性（5 个词）、内容边界（必讲/不讲/禁碰）
2. **页面布局骨架** — 总数分章、目录↔扉页契约、Hero 页定位与配额、rhythm 曲线、非对称/对称版式预算
3. **页面大纲** — 逐页一张表：`title/type/role/rhythm/layout/visual/visual_role/density/anti_pattern/description`
4. **Checklist 自检** — 把下面这些硬指标逐条勾掉

**Hero 页配额**：10 页以上必须有 2–3 页视觉高潮（hero）。经验取 **20–30%**（16 页 → 4 页）。
**rhythm 曲线**：peak / transition / valley 三类逐页标注，**禁止连续 ≥3 页 valley**。
**版式预算**：非对称版面 ≥ 40%，相邻两页版式不得相同。
**目录↔扉页契约**：目录声明 N 章，全篇 `type: section` 扉页必须正好 N 个，编号连续、标题逐字一致。

## 阶段 4 · 锁设计规范 → DESIGN.md

七节结构（模板见 `assets/DESIGN.template.md`，规则区间见 `design-md.md`）：

1. 画布与全局母版（A/B/C 三区具体 px）
2. 颜色系统（≤4 hex + 中性辅助色；面积分配；渐变与半透明策略；禁忌）
3. 字体系统（2 套家族；字号层级表：字号/字重/行高/字距/用途）
4. 信息密度门禁（留白上限、正文字数下限、容器填充率、底栏锚定、兄弟卡对齐）
5. 配图系统（统一美术风格词、配图清单表、允许 SVG 的元素、素材处理、图表配色、禁忌）
6. **页面映射表** — STORY.md ↔ slides/*.slide 的**契约**，逐页给：序号/文件/类型/角色/版式/主视觉/字数/留白%/色彩分配/关键约束
7. 逐页动笔自检清单

> 第 6 节那张表是全流程的中枢：写作时逐页对照它，写完用它验收。

## 阶段 5 · 生成主视觉

- 所有 prompt **复用同一套风格后缀词**（统一美术类型，禁止摄影/插画/3D 混用）。
- 必须生图的场景：具象场景（城市、办公室、工厂、校园…）、人物群像、风格化画面、占 B 区 ≥30% 的大图。
- 允许 `<svg>` 的：流程/时间轴/矩阵/漏斗/架构图/巨型数字/角标/背景网格等**结构化或低语义**元素。

## 阶段 6 · 素材加工

⚠️ **生图返回顺序常与 prompt 顺序错位** —— 必须**逐张 Read 核对**真实内容、比例、清晰度、风格一致性，
再重命名映射到 DESIGN.md。**禁止按时间戳盲映射。**

处理后：
- 裁掉右下角工具水印（`prep_images.py --crop-watermark`）
- 竖图若要用在大图位，切成 N 条横带避免过度裁切
- 文件名用英文短名，禁止中文/空格/特殊字符

## 阶段 7 · 页面构建

逐页写 `slides/NN.slide`。骨架公式、Flexbox 用法、字号表、图片三种用法见 `layout-recipes.md`。

**写作顺序建议**：先写 1 页（通常封面）跑通 lint，确认环境无误，再批量写其余页。

## 阶段 8 · 校验写入（逐页内循环）

```bash
# 对每一页：
lint --dsl-file slides/NN.slide        # 返回 JSON，看 "ok"
  → ok:false → 改源码 → 重跑 lint      # 见 lint-troubleshooting.md
  → ok:true  → upsert-dsl --dsl-file slides/NN.slide
```

**这是门禁，不是验收**：`ok:false` 的页**压根不许进 pptx**。第一轮大量报溢出是正常的
（本项目 16 页第一轮 6 页报错），全部拦在写入之前。

用 `scripts/build_deck.sh` 可以一次性跑完整个循环（自动跳过未通过的页并列出）。

## 阶段 9 · 交付

`present_files` 打开成品。**注意语义**：这是交付给用户看，不是我在自查——
整条链路里**只有人能看见画面**。

---

## 两个必须牢记的认知

1. **"不写坐标" ≠ "不参与排版"**。省下来的算账精力全用在定规则上（字号/分栏/比例/高度）。
   规则决定一切，引擎只是执行者。
2. **lint 是门禁，不是验收**。它回答"算得对不对"，不回答"好不好看"——纯数值判断，零审美成分。
   美感没有机器兜底，所以规范必须前置锁死。

## 改稿（成品已存在时）

没有撤销。改一页 = 改 `slides/NN.slide` 源文件 → `lint` 通过 → `upsert-dsl` 覆盖该页。

```bash
slidep.sh upsert-dsl "<deck>.pptx" --dsl-file slides/13.slide --page-index 12   # 12 = 第 13 页，0 基
```

省略 `--page-index` = 追加新页；指定 = **替换**该页（0 基索引）。这就是全部的"增删页"能力。
