# 分析报告结构与可视化选型指南

---

## 一、报告标准结构

建议采用「五段式」，其中第五段（溯源校验）是本技能区别于普通数据分析的关键。

```
1. 数据概览      数据规模、时间范围、核心字段、口径说明
2. 核心指标      KPI 卡片：总额、数量、均值及其两套口径
3. 分项分析      趋势 / 结构 / 对比 / 漏斗（每节含图 + 结论）
4. 数据质量      问题清单（分级）+ 各表评级 + 处置建议
5. 溯源校验      源文件指纹 + 对账表 + 修正记录 + 未校验部分披露
```

### 各段落要点

**1. 数据概览**
- 明确的记录数、表数、时间范围
- **口径声明**：是否含取消/退款单、是否剔除异常值、时间粒度
- 若存在多张表，说明各表关系（同源 / 独立口径 / 副本）

**2. 核心指标**
- 存在多种口径时**必须并列展示**，不要只给一个数字

| 指标 | 全部口径 | 有效口径（剔除取消/退款） |
|---|---|---|
| 总销售额 | ¥2,372,265.58 | ¥2,586,835.96 |
| 订单数 | 520 | 444 |
| 平均客单价 | ¥4,562.05 | ¥5,826.21 |

- 给出**口径选择建议**：对外报规模用哪个、评估成交能力用哪个

**3. 分项分析**
- 每节结构固定为：`小标题 → 引导语（说明数据源与口径） → 图表 → 结论要点（编号列出）`
- 结论必须带数字，避免"有所增长""表现较好"这类无量化表述
- 指出**异常点**而不只是描述现象（如"iOS 转化率垫底，存在浏览—下单断点，建议排查结算链路"）

**4. 数据质量**
- 问题清单表：`数据表 | 类型 | 问题描述 | 影响行数 | 级别`
- 各表质量评级表，让读者一眼看出哪张表可用
- 处置建议要可执行（剔除某表 / 补全某行 / 加校验规则）

**5. 溯源校验**（关键章节）

必须包含四块内容：

```markdown
### 源文件指纹
路径 / 大小 / 修改时间
MD5     <hash>
SHA256  <hash>
※ 若源文件哈希与上方一致，即可确认报告依据的是同一份原始数据

### 逐项对账表
| 校验项 | 报告值 | 独立重算值 | 溯源路径/计算式 | 结论 |

### 校验发现的修正
| # | 涉及项 | 原稿表述 | 校验后事实 | 处理 |

### 诚实披露：未能校验的部分
- 哪些数据无第三方可勾稽来源，本报告不对其做正确性背书
```

## 二、图表选型决策表

| 分析目的 | 推荐图表 | 避免 | 说明 |
|---|---|---|---|
| 时间趋势 | 折线图 | 饼图 | 折线能体现连续性与拐点 |
| 期间增减 | 柱状图（红涨绿跌） | 折线 | 突出正负对比 |
| 结构占比 | 堆叠柱 / 条形图 | 饼图（>5 类） | 饼图超过 5 类难以辨认 |
| 排名对比 | 横向条形图 | 竖向柱 | 横条便于放长标签 |
| 转化漏斗 | 横向条形（递减） | 饼图 | 配合占比标注 |
| 相关关系 | 散点图 | 折线 | 折线暗示因果，散点更客观 |
| 多指标对比 | 分组柱 / 雷达图 | 多轴折线 | 多轴折线易误导 |
| 分布形态 | 直方图 / 箱线图 | 均值单值 | 均值掩盖分布差异 |

### 何时必须看图说话

图表下方**必须**配结论文字。只有图没有解读，等于把工作丢回给读者。

## 三、配色规范

### 涨跌色（重要）

**中国业务语境：涨 = 红，跌 = 绿**（与欧美相反）。财务、销售、股价类图表必须遵循。

```python
UP   = "#D93B3B"   # 增长 / 上涨 → 红
DOWN = "#1E9E5A"   # 下降 / 下跌 → 绿
```

### 通用色板（明主题）

| 用途 | 色值 |
|---|---|
| 主色（强调、主线） | `#2F6BFF` |
| 辅色 | `#7A5AF8` |
| 第三色 | `#12B76A` |
| 文字主色 | `#1B2430` |
| 文字次要 | `#5B6879` |
| 边框 / 分隔线 | `#E3E8EF` |
| 页面背景 | `#F4F6FA` |
| 卡片背景 | `#FFFFFF` |

### 暗主题

| 用途 | 色值 |
|---|---|
| 页面背景 | `#0F1218` |
| 卡片背景 | `#181D26` |
| 文字主色 | `#E8EDF5` |
| 文字次要 | `#98A2B3` |
| 涨 / 跌 | `#FF5C5C` / `#22C55E` |

### 提示块语义色

| 级别 | 含义 | 明主题背景 / 边框 / 文字 |
|---|---|---|
| `info` | 说明、口径解释 | `#F1F6FF` / `#C8DAFB` / `#2B4C8C` |
| `ok` | 校验通过 | `#EAF7EF` / `#B9E3CB` / `#146B41` |
| `warn` | 需注意但不阻塞 | `#FFF6E5` / `#F0DBA8` / `#8A6200` |
| `risk` | 重要风险点 | `#FDECEC` / `#F5C6C6` / `#8C2F26` |

**暗主题必须用深底浅字**，不可直接复用明主题的浅色背景。

## 四、数字呈现规范

| 类型 | 规范 | 示例 |
|---|---|---|
| 金额 | 人民币符号 + 千分位 + 2 位小数 | `¥2,372,265.58` |
| 大额辅助 | 可加万元/亿元换算 | `¥237.23 万` |
| 百分比 | 2 位小数 | `23.73%` |
| 环比 | 带正负号，红涨绿跌 | `+194.1%` / `-62.5%` |
| 序号/编号 | 保留原格式，不转数值 | `ORD202500266` |
| 计数 | 千分位 | `1,747` |

**注意**：报告展示用 2 位小数，但**底层计算必须用全精度**，否则会产生舍入误差累积。
在对比报告中，独立重算值可展示更多位（如 `23.7288%`）以体现精度。

## 五、`html_report.py` 的 JSON 输入规范

完整示例见 `references/report-spec-example.json`。

```json
{
  "title": "报告标题",
  "subtitle": "副标题",
  "theme": "light",
  "tags": ["标签"],
  "kpis": [
    {"label": "指标名", "value": "¥1,234", "sub": "补充说明", "highlight": true}
  ],
  "sections": [
    {
      "heading": "章节标题",
      "lead": "引导语",
      "kpis": [{"label": "", "value": "", "sub": ""}],
      "charts": [
        {"type": "line|bar|hbar", "title": "图标题",
         "categories": ["类目"],
         "series": [{"name": "系列名", "data": [1, 2]}],
         "palette": "auto|updown",
         "ylabel": "Y 轴标签", "format": "k", "rotation": 45, "height": 4.2}
      ],
      "tables": [
        {"title": "表标题", "headers": ["列"], "rows": [["值"]], "align_right": [0]}
      ],
      "notes": [{"level": "info|ok|warn|risk", "html": "提示内容"}]
    }
  ],
  "footer": "页脚"
}
```

### 关键字段说明

| 字段 | 取值 | 作用 |
|---|---|---|
| `charts[].type` | `line` / `bar` / `hbar` | 折线 / 柱状 / 横向条形 |
| `charts[].palette` | `auto` / `updown` | `updown` 启用涨红跌绿（仅 `bar` 有效） |
| `charts[].format` | `k` | Y 轴以千为单位显示 |
| `tables[].align_right` | 列索引数组 | 指定右对齐列（数值列推荐右对齐） |
| `tables[].raw_html` | `true` | 允许单元格内容含 HTML（默认转义，防注入） |
| `notes[].level` | `info`/`ok`/`warn`/`risk` | 决定提示块配色 |

### 生成命令

```bash
python scripts/html_report.py result.json --out report.html --theme light
```

输出为**单文件自包含 HTML**，图表已 base64 内嵌，可直接分发、离线打开、邮件发送。
