# 数据质量检查清单

用于系统性诊断 Excel/表格数据的质量问题。按五大类 + 逻辑一致性逐项检查，
每项问题必须给出**可复现判据**（字段 + 条件 + 命中行数 + 样本主键）。

---

## 一、五大类检查项

### 1. 缺失值（Missing）

| 检查点 | 判据 | 处理建议 |
|---|---|---|
| 空单元格 | `isna()` 或 空串 / 纯空白 | 按字段性质决定：关键字段剔除该行，非关键字段保留并标注 |
| 空串伪装成有效值 | `str.strip() == ""` 但有值 | 统一转为真正的空值，避免聚合时被当作有效数据 |
| 整列为空 | 非空计数 = 0 | 确认是否字段废弃 |
| 高缺失率字段 | 缺失率 > 50% | 在报告中显式提示"慎用"，不可默认其代表性 |

**注意**：`pd.read_excel` 会把空单元格读成 `NaN`，但把空串读成 `''`。
两者语义不同，清洗时需区分处理——空串往往代表"录入时留空但占位"，`NaN` 代表"真的没有"。

### 2. 重复值（Duplicate）

| 检查点 | 判据 | 说明 |
|---|---|---|
| 全行完全重复 | `df.duplicated().sum()` | 通常为导出重复，直接去重 |
| 主键重复 | 主键列 `duplicated()` | ★ 严重：需人工判定保留哪条 |
| **跨表重复** | 主键交集占比 | ★★ 最易误判，见下文专节 |

### 3. 异常值（Outlier）

| 检查点 | 判据 | 说明 |
|---|---|---|
| 数值越界 | 超出业务合理区间 | 如单价 ≤ 0、满意度超出 1-5、折扣率超出 [0,1] |
| 极端离群 | 远超均值（如 > 100 倍） | 可能是单位错误（分/元混用）或录入多打零 |
| 逻辑矛盾 | 字段间关系不成立 | 如"已完成"订单金额为 0、"未发货"却有签收时间 |
| 数值为 0 | 需结合业务判断 | 0 可能是合法值（赠品、退款后金额），也可能是缺失的替代 |

**⚠️ 必须先区分「真异常」与「业务特殊值」**，见第四节。

### 4. 格式错误（Format）

| 检查点 | 判据 | 影响 |
|---|---|---|
| **数值列混入文本** | 该列存在无法转数值的值 | ★ 高危：整列 dtype 退化为 object，所有聚合/排序失效 |
| 日期为文本存储 | 形态匹配日期但 dtype 为 object | 无法按时间排序、分组、计算区间 |
| 日期格式不统一 | 同列出现多种格式 | 解析后可能产生错值 |
| 首尾空格 | `str != str.strip()` | ★ 隐蔽：`"已完成"` 与 `"已完成 "` 被当作两个不同枚举值 |
| 全角/半角混用 | 数字或标点全半角不一致 | 影响匹配与解析 |
| 千分位/货币符号混入 | 如 `"1,234元"` | 需清洗后才能计算 |

**识别数值列混入文本的通用方法**：

```python
def to_num(v):
    if v is None or (isinstance(v, float) and pd.isna(v)):
        return None
    if isinstance(v, (int, float)):
        return float(v)
    try:
        return float(str(v).strip().replace(",", ""))
    except (ValueError, TypeError):
        return None

# 若某列「非空值中可转数值的比例」介于 0 与 1 之间 → 混入文本
ratio = df[col].dropna().map(lambda v: to_num(v) is not None).mean()
if 0 < ratio < 1:
    print(f"★ 字段 {col} 混入文本，需清洗")
```

### 5. 非法取值（Invalid Value）

适用于**枚举型字段**（区域、状态、渠道、设备类型等）。方法：建立合法取值白名单，取差集。

```python
whitelist = {"华东", "华南", "华北", "华中", "西南", "东北"}
illegal = set(df["大区"].dropna()) - whitelist
if illegal:
    print(f"★ 非法取值：{illegal}")
```

**同类问题**：同义异形（`"华东"` vs `"华东地区"`）、大小写不一致（`"iOS"` vs `"ios"`）、
中英文混用（`"Mac"` vs `"苹果"`）——这些会让分组统计被错误拆分。

## 二、逻辑一致性校验（数值可验证的部分）

| 校验类型 | 方法 | 示例 |
|---|---|---|
| **公式反算** | 用其他字段重算目标字段 | `销售额 == 数量 × 单价 × (1 - 折扣率)` |
| **恒等式校验** | 分项之和 == 合计 | 各月销售额之和 == 全年合计 |
| **外键完整性** | 明细外键 ⊆ 维表主键 | 产品编号必须存在于产品维表 |
| **主键唯一性** | 主键无重复 | 订单编号唯一 |
| **状态-数值一致性** | 状态与数值逻辑自洽 | "已取消"金额应为 0；"已退款"金额应为负 |
| **跨表勾稽** | 明细聚合 == 汇总表 | 见第三节 |

**公式反算要设容差**：浮点运算存在精度误差，建议阈值 `0.02`（金额类，单位：元）。
不要用等值判断，否则会把正常的浮点误差报成错误。

## 三、跨表问题的两个高危误判

### 误判 1：用笛卡尔积判定「汇总表缺行」

**错误做法**：
```python
# ✗ 错误：假设每个维度组合都应该存在
expected = {(m, r) for m in all_months for r in all_regions}
missing = expected - actual_pairs   # → 把"本就无业务"误判为缺行
```

**正确做法**：**以明细表实际出现的组合为基准做双向勾稽**。

```python
# ✓ 正确：只有当明细里确实有业务、汇总里却没有，才是真缺失
detail_pairs  = set(zip(detail["月份"], detail["大区"]))
summary_pairs = set(zip(summary["月份"], summary["大区"]))

真缺失      = detail_pairs - summary_pairs   # 明细有、汇总无 → 严重
凭空多出    = summary_pairs - detail_pairs   # 汇总有、明细无 → 需解释
```

**为什么**：某月某区域可能"本就没有任何订单发生"，汇总表不列该行是**正常的无数据省略**，
不是数据丢失。用笛卡尔积会把这类正常省略全部误报为高危缺失。

**补充验证**：对每个组合还要比对**订单数**是否一致，才能确认两表真正同源。

### 误判 2：把「脏数据副本」当成「补充数据」直接合并

多表数据集中，若某表主键 100% 命中另一表，需要先判断它是**增补**还是**副本**。

```python
A_ids, B_ids = set(A["订单编号"]), set(B["订单编号"])
inter = A_ids & B_ids
print(f"A={len(A_ids)} B={len(B_ids)} 交集={len(inter)} 仅B={len(B_ids - A_ids)}")

# 判定：
#   交集占比高 + 仅B 为空      → B 是 A 的副本（可能是脏数据版本）
#   交集占比低 + 仅B 有大量数据 → B 是补充数据，可合并
#   交集高 + 仅B 也有数据      → 混合情况，需逐字段比对
```

**若判定为副本，还必须逐字段比对**：找出被篡改的字段，判断是"更早版本"还是"被污染版本"，
再决定剔除还是以某一版为准。

```python
common = sorted(A_ids & B_ids)
m = A[A["订单编号"].isin(common)].set_index("订单编号").sort_index()
b = B[B["订单编号"].isin(common)].drop_duplicates("订单编号").set_index("订单编号").sort_index()

diff_fields = {}
for col in A.columns:
    d = (m[col].astype(str) != b[col].astype(str)).sum()
    if d:
        diff_fields[col] = int(d)
print("被改动的字段:", diff_fields)
```

**结论表述**：副本表应**剔除而非合并**，并在报告中说明理由与影响（"若合并将造成重复计算与脏值污染"）。

## 四、业务特殊值 ≠ 数据错误

以下情况**不应判为错误**，但应在报告中标注：

| 现象 | 性质 | 处理 |
|---|---|---|
| 退款/取消单金额为负或 0 | 业务正常 | 标注"退款冲抵"，建议单列退款字段而非混入销售额 |
| 赠品 / 样品单价为 0 | 业务正常 | 单独归类，不计入客单价 |
| 某维度组合在汇总表无行 | 无业务发生 | 正常省略，非缺失 |
| 首月/末月数据不完整 | 统计周期边界 | 在报告中说明周期范围，避免与完整周期直接对比 |
| 负数出现在"调整额""冲抵"类字段 | 业务正常 | 按字段语义判断 |

**判据**：如果这些值能与**状态字段**（如"已退款"）或**业务规则**一一对应，
则属业务逻辑，不是数据错误。检验方法：

```python
# 交叉验证：异常值是否都能被业务状态解释
bad = df[df["销售额"] <= 0]
print(bad["订单状态"].value_counts())
# 若全部落在 {"已取消", "已退款"} → 业务正常
# 若出现 {"已完成", "已发货"} → 真异常，需追查
```

## 五、问题分级标准

| 级别 | 判定标准 | 处置 |
|---|---|---|
| **高危** | 导致计算错误或结论失真；污染主分析表 | 必须修复或剔除后才能出报告 |
| **中等** | 影响局部准确性或可读性；需人工确认 | 修复并说明；不修复须在报告中标注 |
| **提示** | 数据完整但存在风险点；或属业务正常现象 | 记录备查，不阻塞交付 |

**每条问题都应包含**：涉及表 → 问题类型 → 具体描述（含行数） → 样本主键 → 级别。

## 附：实战案例（真实数据集）

某销售数据集含 7 张表。检查结果：

| 数据表 | 评级 | 关键问题 |
|---|---|---|
| 订单明细_A（520 行，主表） | **优** | 仅"来源备注"缺失 113 处（21.73%），不影响主指标 |
| 订单明细_B（60 行） | **差** | 60 条订单号 100% 命中 A 表，字段被系统性篡改 |
| 月度销售汇总（125 行） | **优** | 与主表 100% 勾稽；6 行负销售额系退款冲抵 |
| 月度经营KPI（126 行） | **优** | 数据完整，但为独立放大量级口径（销售额约为主表 55.9 倍） |
| 用户行为日志（900 行） | **优** | 转化标记与事件类型零矛盾 |

**B 表被篡改的字段**（逐字段比对得出）：

| 字段 | 污染形态 | 影响 |
|---|---|---|
| 大区 | 出现"华东地区"（非法枚举） | 分组统计被拆分 |
| 客户满意度 | 出现 7（合法范围 1-5） | 均值被抬高 |
| 数量 | 出现 -3 | 合计被拉低 |
| 单价 | 混入"约899元"（文本） | 整列无法计算 |
| 订单状态 | 出现"已完成 "（尾随空格） | 与"已完成"被当作两个值 |
| 折扣率 | 出现 1.25（超出 [0,1]） | 反算公式不成立 |
| 销售额 | 出现 1000 万级峰值与空值 | 合计严重失真 |

**关键教训**：
1. 判"月度销售汇总是否缺行"时，用笛卡尔积误报出 1 个假缺失 —— 实际该组合订单数为 0，属正常省略。
2. 复核脚本自身也可能有 bug（曾用升序切片取"降幅 TOP3"，导致排序反向而误报报告错误）。
   **复算不一致时，先怀疑校验脚本。**
3. 百分比比对需设阈值（建议 5e-5），区分"呈现精度差异"（23.73% vs 23.7288%）与"真实计算错误"。
