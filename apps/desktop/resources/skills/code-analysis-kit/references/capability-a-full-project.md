# 能力 A｜完整项目代码分析

输入项目路径，产出项目结构、关键逻辑、模块依赖、潜在风险与现有测试资料，并给出建议测试清单。

## 流程

按 L1 → L2 → L3 → L4 执行，具体动作如下。

### 步骤 1｜任务识别（L1）
- 确认项目路径（本地文件夹，绝对路径优先）并校验其存在且为目录，再定分析深度与包含 / 排除范围。
- 输出任务卡。

### 步骤 2｜项目理解（L2）
- 运行 `python scripts/scan_project.py <项目路径> --json`。
- 读取结果，确认技术栈、目录职责分层、入口文件、测试现状。
- 对关键模块做定向深读，绘制模块依赖与 1–3 条核心调用链。
- 产出"项目地图"。

### 步骤 3｜逻辑与风险分析（L3）
- 按逻辑检查清单逐维度扫描（正确性、错误处理、状态、并发、性能、安全、可维护性、一致性）。
- 对高风险模块与核心调用链重点检查。
- 对现有测试：核对覆盖到的模块与明显缺口（核心逻辑无测试、仅测 happy path、测试与实现漂移）。
- 可选：按语言运行静态分析工具补充证据。

### 步骤 4｜结果规范化（L4）
- 问题分类 + 编号，逐条补证据与风险等级。
- 生成测试建议清单（重点来自"风险驱动补充"与"测试缺口"）。
- 按报告结构成文。

## 输出要点

- 项目地图必须完整，作为问题定位的上下文。
- 风险聚焦"真正会出事的点"，不堆砌风格问题；P3 类问题可归并简写。
- 测试清单要能直接指导"下一步补哪些测试"。

## 质量自检

- [ ] 任务卡承诺的范围已全部覆盖，或说明了未覆盖原因。
- [ ] 每个问题都有 `路径:行号` 级证据。
- [ ] 风险等级都有一句依据。
- [ ] 测试建议覆盖了变更 / 影响 / 风险三来源。
- [ ] 未覆盖与不确定项已如实列出。
