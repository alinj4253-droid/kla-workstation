# PPT 智能体 · 能力包（自包含说明）

本版本在原有确定性 `DeckSpec → PPTX` 引擎外，加入新版 `@tencent/slidep 6.5.1` 的本地主题契约和 Yoga 页面布局校验能力。slidep 只作为主题/布局增强器，默认不替换稳定的 PPTX 生成链：其 `create` 和 `upsert-dsl` 需要外部文档服务，不能作为工作站离线生成的前置条件。

> **读这一份文件就够了。** 它说明了包里有什么、每样东西怎么用、跑不了时该怎么告诉用户。
> 不需要任何外部上下文——把它连同整个目录交给任何一个能读文件、能跑命令的智能体即可。

---

## 0. 这是什么

把"一批材料 + 一句话需求"变成一份**原生可编辑的 .pptx**，并支持**用自然语言改到定稿**。

三条写死在架构里的前提：

1. **单一真源 = 页面语义**。语言模型只产语义，**一个坐标、字号、颜色都不产**；几何由本包的确定性引擎计算。
2. **PPTX 是唯一产物真源**。预览由该 pptx 反向渲染，**禁止另做一套 HTML/前端渲染**（两套渲染必然不一致）。
3. **交付前真渲染自检**，不通过不给导出。

为什么这么设计：坐标算不准、标点会漏检、元素会漏画——这些**不能交给语言模型每次重新判断**，必须由确定性的代码保证。模型负责"判断"，引擎负责"算准"。

## 2. 装上之后，第一步永远是环境自检

```bash
python scripts/run.py          # 等价于 python scripts/run.py doctor
```

它会输出一份报告，把结论落进三档之一：

| 档 | 含义 | **你应当怎么对用户说** |
|---|---|---|
| `full` | 生成 + 质检 + 真渲染 全可用 | "环境齐全，可以直接做。" |
| `partial` | 能生成 pptx、能跑结构质检，**但不能真渲染** | "我可以生成 PPT 和做结构检查，但**这台机器没装渲染器**，所以我没法用渲染图做视觉自检。成品的视觉效果需要你在 PowerPoint/WPS 里打开确认一下；要补上这一步，装个 LibreOffice 就行。" |
| `blocked` | 缺关键依赖，连生成都做不了 | "这台机器缺 Python 依赖（报告里列了），装齐后我就能开始。命令：`pip install python-pptx Pillow pypdfium2`。" |

**不要假装能做。** 做不到的部分必须由你明确报出来——这是本包的设计要求，也是用户最需要知道的信息。`local_ppt_doctor` 还会报告新版 slidep 是否随 Electron 安装；主题目录和页面布局校验不可用时，不影响原有 PPTX 生成。

### 2.1 新版组件增强能力

- `local_ppt_theme_list`：读取 `vendor/slidep/resources/themes` 中的设计契约，按关键词筛选主题。返回主题名称、描述和契约文件名，不会把主题绑定到某个智能体。
- `local_ppt_dsl_validate`：把单页 `.slide` JSX 交给 slidep 的 Yoga 布局校验器，返回 `ok` 和诊断信息。它不会执行任意模型代码，也不会生成成果文件。
- `local_ppt_build` 仍是交付入口。语义 JSON 是唯一内容真源，必须经过当前引擎的 schema、QC 和真实渲染门禁。

slidep 的 `create`、`upsert-dsl` 在其发布包中会访问外部本地文档服务，因此没有接入默认生成路径。若未来工作站提供该服务，可通过 `KLA_SLIDEP_ENGINE` 和 `KLA_SLIDEP_NODE` 配置实验性链路，但仍需保留当前 PPTX 质检和成果回执。
如果连命令都跑不了（例如你的运行环境没有执行能力、无法访问文件系统），就直接说：
"这个包需要能执行 Python 命令的环境；我当前环境不具备，所以只能提供说明，不能产出文件。"

## 3. 上手（三条命令）

```bash
pip install -r scripts/requirements.txt                  # 1. 装依赖
python scripts/run.py doctor                             # 2. 自检
python scripts/run.py all assets/deck.sample.json -o out.pptx   # 3. 跑通样例
```

第三步会依次：编译 → 质检 → 渲染。**退出码 0 才算通过**，产物在 `out.pptx` 与 `out_render/`。

## 4. 命令参考

| 命令 | 作用 | 退出码 |
|---|---|---|
| `run.py doctor` | 环境自检：能做什么、缺什么、怎么补 | 0 可用 / 3 不可运行 |
| `run.py check spec.json` | 只校验语义契约 | 0 通过 / 1 不合规 |
| `run.py build spec.json -o out.pptx` | 编译（默认带契约校验，`--loose` 可放宽） | 0 / 1 |
| `run.py qc out.pptx --spec spec.json` | 质量门禁（给 spec 才做漏画比对） | 0 通过 / 2 有阻断 |
| `run.py render out.pptx -o dir` | 真渲染 → PDF + 逐页 PNG + 缩略图网格 | 0 |
| `run.py all spec.json -o out.pptx` | 编译→质检→渲染 一条龙 | 0 / 1 / 2 |
| `run.py layouts` | 列出支持的块类型与版式 | 0 |

所有命令输出 JSON（除 `doctor` 与 `layouts`），可直接被程序解析。

## 5. 输入契约：deck spec

### 5.1 整体结构

```json
{
  "title": "汇报标题",
  "design_system": "modern-tech",
  "pages": [
    { "page_id": "p01", "kind": "cover", "page_job": "立住主题与场合",
      "title": "…", "meta": ["场合", "日期", "单位"],
      "blocks": [ { "type": "lead", "text": "…" } ] }
  ]
}
```

- `design_system`：预设 id（`modern-tech` 炭黑+青绿 / `classic-pro` 墨蓝+砖橙 / `deep-premium` 深色+金），或对象（`{"preset": "...", 覆盖字段...}`）
- `page_job`：**这页要干什么，一句话**——必填，它是所有版式与内容决策的判据
- `kind`：`cover` 封面｜`section` 章节页｜`content` 内容页｜`closing` 收尾页

### 5.2 块类型（12 种）

| type | 用途 | 关键字段 |
|---|---|---|
| `lead` | 页头下的一句话导语 | `text` |
| `card` | 卡片 | `title` `body` `items[]` `index` `mark` |
| `bullets` | 条目组 | `items[]` |
| `kpi` | 英雄数字 | `value` `unit` `label` `note` `source` `mark` |
| `steps` | 流程步骤带 | `items[]`（`{title, body}`，顺序即展示顺序） |
| `chart` | 柱状图 | `data[]`（`{label, value, hot?}`）`note` |
| `compare` | 两列对比 | `left{title,body,items}` `right{…}` |
| `matrix` | 覆盖矩阵 | `rows[]` `cols[]` `dots[]` |
| `image_slot` | 配图位（虚线占位） | `label` `hint` `side` |
| `concl` | 底部结论条 | `text` |
| `quote` | 引语 | `text` `source` |
| `table` | 表格 | `header[]` `rows[][]` `note` `col_ratios[]` |

### 5.3 第一号红线：语义层不许携带几何

块里出现 `x / y / w / h / top / left / width / height / size / color / fill`，**校验直接失败**
（例外：`compare.left / compare.right` 是"左列/右列"的语义分组名）。

理由：一旦允许语义层写坐标，就退化成"每次现场手写排版"——可校验、可换模型、可只重算一页，这些全都失去。

### 5.4 数据严谨（校验器会提示）

| 情形 | 必须怎么做 |
|---|---|
| 引用外部数据 | 填 `source`（来源） |
| 自己加总/求平均 | 填 `assumption`，写出算式与口径 |
| 无法核实的推断 | 显式标注为"假设"，不得与公开数据混为"事实" |
| 分子分母不同的相似百分比 | 只放一个进标题/英雄数字，另一个降到页脚来源行小字 |

## 6. 版式库与消费关系

引擎按块类型组合**自动选版式**，并施加多样性约束：**连续 3 页同版式即换**（换的是形态，不是颜色）。

| 版式 | 消费哪些块 | 注意 |
|---|---|---|
| `cover` | `title` `meta` + 第一个 `lead` | |
| `section` | `title` `page_job` | 不画 blocks |
| `statement` | 第一个 `bullets`/`quote`/`card` | |
| `cards` | `lead` + `card`×N + `bullets` + `concl` | 单卡+bullets 自动左右分栏；多卡时不再画 bullets |
| `two_col` | `compare` 或前两张 `card` + `concl` | 不画 `lead` |
| `steps` | `lead` `steps` `chart` `concl` | |
| `kpi_focus` | `lead` + `kpi`×N +（`chart` 或前 3 张 `card`）+ `concl` | |
| `chart_concl` | `lead` `chart` + 第一张 `card` + `concl` | 只画第一张 card |
| `image_led` | `image_slot` +（`bullets` 或第一张 `card`）+ `concl` | 配图位按 16:9，占版面 42% |
| `table` | `table` + `concl` | |

> **引擎不会静默丢弃内容。** 放了版式不消费的块，`qc` 的「疑似漏画」断言会在交付前抓出来。
> 这是刻意的：宁可报错，也不交付一份"看起来对、却少画了东西"的文件。

## 7. 工作流（六个阶段）

```
① 投料 → ② 理解+大纲 ⛔阻断点 → ③ 生成 → ④ 对话改稿（↔③循环）→ ⑤ 预览 → ⑥ 交付
```

三个不可动摇的节点：

- **② 必须等用户确认大纲再往下。** 用户不给反馈 = 待定，不默认放行。跳过这步直接生成全套，是最大的返工来源。
- **③ 生成后必须真渲染自检**（见 §11）。没经过渲染复核的产出不许交给用户。
- **④ 改稿只动被指的那一页。** 整份重生成会毁掉已确认的全部内容。

各阶段落地：

| 阶段 | 做什么 | 用什么 |
|---|---|---|
| S1 材料接入 | 解析 Word/PDF/Excel/PPT/图片，**表格保留行列结构不拍平**，解析结果回显给用户核对 | 宿主的文件读取能力；解析后整理成素材 |
| S2 大纲（⛔） | 判场景 → 出页级 roster（每页一句"这页要干什么"）+ 标题连读测试 → **等确认** | 无命令，纯对话 |
| S3 生成 | 写 deck spec → 编译 → 质检 → 渲染 | `check` → `build` → `qc` → `render` |
| S4 改稿 | 定位到页 → 改该页块 → 只重编译该页 → 只重渲染该页 | 改 spec 的对应节点后重跑 |
| S5 预览 | 用渲染出的逐页 PNG / PDF 给用户看（**不是另做 HTML**） | `render` 的产物 |
| S6 交付 | pptx + 逐页结构清单 + 质检报告 | `qc` 输出 + 文件本身 |

> ⚠ **S4 的"只重做一页"目前是效率约束、不是引擎特性**：引擎支持按页拆分 spec 后单独编译。要让改稿真的只重算一页，把 deck 拆成每页一个 spec，或用外层服务按页缓存——见 §13 的扩展建议。

## 8. 内容规则

**结构**
- **一页一消息**：标题里出现"和/以及"就拆两页。
- **结论先行**：标题是完整句结论（行动标题），不是主题标签。标题 ≤15 词 / ≤2 行 / 主动语态 / 尽量量化。
- **只读标题测试**：把全部标题连起来读，故事必须成立。
- **60 秒规则**：一页 60 秒讲不完就拆。
- 不做泛泛的背景铺垫，每页落到本次具体内容。

**文本饱满度**
- 正文写**完整句**，补全清单子项，加解释性收尾句。
- **压缩只允许用于辅助元素**（关键词胶囊、标签、角标）。
- 判断标准：这页的论据是否完整、是否读得懂、是否需要口头补。

**数据严谨（硬规则）**
- 外部数据必须标 `source`；自算数必须写算式与口径（`assumption`）；推断值必须标"假设"。
- 数字配分母小注（"147 套合格 = 98%（150 套）"）。
- 分母说不清时**只给套数，不给百分比**。
- 商业模型类假设（比例、单价、客户数目标）一律显式标注为假设。

**受众语言分层**
- **图上只放受众听得懂的二分**（如 合格 / 不合格）。
- **内部归因分类下沉到结论文字**，按"构成 → 问题类型 → 下一步"写透。
- 同页术语只能有一个（"未达标 / 不合格"选一个）。

**主线守护（增量编辑最容易踩的坑）**
- 每完成一轮"删/弱化/简化"，回到任务陈述核对两句：这页存在的意义还看得出来吗？标题里的**主线词**还在吗？
- **删内容优先删论据，绝不删主线词。**
- 同一论点的多页，标题必须共享同一个主线词，并把动作词写进去。

**不注水**：页数诚实反映材料，不为"看起来丰富"而加页、加卡、加装饰。

## 9. 设计规则

### 9.1 场景优先（最高优先级，凌驾于本节所有具体参数）

> **不存在"好的配色/排版"，只存在"适合这个场景的配色/排版"。**

拿到任务先判场景，并在回复里写明判定依据：

| 场景 | 讲/读 | 字号 | 配色 | 装饰 |
|---|---|---|---|---|
| 融资 BP（自阅版） | 读 | 9–11pt | 低饱和商务 | 极少 |
| 融资 BP（路演版） | 讲 | 13–15pt 起 | 同上，共用系统 | 极少 |
| 内部汇报 | 讲+读 | 12–14pt | 低饱和 | 少 |
| 咨询报告 | 读 | 9–10pt 可 | 单色系 | **归零** |
| 教学课件 | 看 | **≥18–24pt** | **高对比，可多色** | 中 |
| 产品发布/演讲 | 看 | 大 | **可深色+高饱和** | 可用 |
| 客户方案 | 读+讲 | 11–14pt | 低饱和 | 少 |

判定后才选参数，**不要复用上一次成功的参数**。三个跨场景旋钮：信息密度↔装饰度是跷跷板；字号下限由观看距离决定；色彩数量与使用时长成反比。**"讲"还是"读"决定一半参数。**

### 9.2 配色（引擎已用 tokens 强制，改设计系统即可）

- **面积分级**：底色/中性 **70%** ｜ 主色 **15–20%（只做骨架）** ｜ 点缀 **5–8%**。**主色永不大面积铺底**。
- **全部低饱和**；**禁纯黑纯白**（`#222222` / `#F4F4F2`）；灰阶给 **3–5 阶**；冷暖平衡。
- **对比度**：正文/背景 ≥7:1（投影吃掉一半对比）；只做深字浅底或浅字深底，**禁中间调对中间调**；深底可用亮金，**浅底亮金不可读**。
- **颜色语义全 deck 不变**：绿/主色系=正向，橙=风险，红=负面（不做装饰）。色盲约 8% → 红绿之外加数字/形状双通道。

### 9.3 字体与字号

- 中文用无衬线（思源黑体 / 微软雅黑一类）；**避雷宋体（显老气）、艺术字**。
- **字号阶梯只做 3–4 级，级差 ≥2 倍**；**最大字号只给数字/编号**。
- 同元素全 deck 同字号。放不下是内容问题，不是排版问题。
- **正文下限**（引擎会强制）：卡内正文 ≥11.5pt、小注 ≥10.5pt、胶囊 ≥10pt。版面不够时消化空间，**不允许无下限缩字号**。页脚等品牌标记 8–11pt 属合理例外。

### 9.4 版式与留白

- 一套 deck 用 6–7 种布局；**连续 3 页同布局 = 重复**。
- **留白**：内容页 40–55%，封面/章节页 60–75%；**内容页形状数 9–15 个**——"少"本身就是高级。
- **结构页禁止平级盒子**：核心实体居中放大；演进关系横向展开；底座全宽纵向托底；支撑体系横贯并**向上**赋能（表达"贯穿"而非"之下的一层"）；块间不画无向箭头；每块标注"→ 解决什么问题"；以价值闭环收尾。

### 9.5 图文结合（硬门槛）

- **每页至少 1 个非文字视觉元素，占版面 ≥30%**，不达标该页返工。
- 视觉元素优先级：真实数据图表 > 关系/结构示意 > 几何图标 > **配图位虚线卡**（兜底，不是首选）。
- **流程/对比/层级/分类页禁止只用文字卡横排**，必须转成图形（步骤链/金字塔/漏斗/矩阵/韦恩图/关系图）。
- **有数字就配图**，不让数字只躺在文字里。
- **配图位必须用真实图片比例**（16:9 / 3:2 / 4:3 / 1:1 / 3:4），**禁止通栏扁条**；图片占该页 25–40%，**先给图片排版面再填文字**。
- 全 deck 真实照片 3–6 张，每页最多 1 张；图与文字间距 ≥0.3in。
- 图片处理：冷调化 ≠ 黑白（压红提蓝 + 降饱和 + 混主题色）；图上叠字必须加半透明蒙版。

### 9.6 反 AI 味

避免：紫渐变万能科技感；emoji 配 bullet；圆角卡片+左彩色 border；均匀深蓝底+青紫霓虹；Inter/Roboto 硬套；机器人/大脑/芯片图形做装饰（用抽象几何、节点连接表达"连接、协同、聚合"）。
**没素材就诚实占位**（灰块+文字标签），**没数据写"待提供"，不编造**。
设计里出现能认出的品牌名 → 官方 logo 是必需资产，先联网核实事实再设计。

## 10. 改稿规则（对话交互）

### 10.1 定位

用户一句话（常带页码）→ 解析为「目标页 / 目标块 + 操作类型」。定位不了就反问一句，**不要猜着改**。

### 10.2 操作集

| 类别 | 操作 |
|---|---|
| 文案 | 重写 / 加子项 / 加收尾句 / 缩短（仅限辅助元素） |
| 结构 | 增页 / 删页 / 调序 / 拆页 / 并页 |
| 版式 | 换一种版式排法 |
| 视觉 | 换设计系统 / 换主色 / 换配图 |
| 数据 | 改数字 / 加一列 / 换口径 |
| 锁定 | 锁定版式、锁定文案（锁定后不得改动该部分） |
| 版本 | 回滚到上一版 |

### 10.3 纪律

- **只重编译、只重渲染受影响的那一页**，其余页不动。
- 改完做**主线检查**：页 job 是否还看得出来、标题里主线词是否还在；删掉的是主线词就告警并请用户确认。
- 结构改动后**页码与编号全量重排**（封面 01/N、每页 chip、页脚"0X / 0N"）；引擎已自动处理页码，但页内自定义编号要自己核对。
- 改完必须**重新真渲染**该页复检。

### 10.4 用户手工改过的版本回传时

1. **先验证文件真是他改过的**（时间戳 + 内容抽查）。若与自己上一版逐字相同 → 停下来告诉用户（多半发错或没保存），**不要基于旧产物重做**。
2. 用户定的是**骨架与文字**，任务是**外科式修补**，不是拿自己上一版整块重写——整块重写会抹掉他的手改。
3. 只做：删错误残留、补缺失解读句、统一数字格式、清脏字符；**文字风格与坐标尽量不动**。
4. 跨页复制残留要逐页核对：每句数据必须属于该页的验收项与样本量。
5. **尊重用户当前的骨架**，不要重新套用自己上一版的结构。

## 11. 质量门禁（交付前必过）

### 11.1 引擎自动跑的（`qc` 命令，机器断言，全量）

| 断言 | 说明 |
|---|---|
| 标点零残留 | 遍历每页 XML 的文本节点，断言不含半角 `( ) , : ;` |
| 字号下限 | 卡内正文 ≥11.5pt 等（超限报 warn） |
| 页码连续 | 逐页核对页码是否存在 |
| **元素完整性（漏画检查）** | 以 pptx **实际绘制内容**为准，与 spec 该画的内容做**集合比对**，缺一个即报 |
| 页数一致 | pptx 页数 vs spec 页数 |

`qc` 返回 `ok: true` 才允许交付；有 `blocked` 级问题**不许导出**。

### 11.2 必须由你（或用户）亲自看的（引擎查不出）

1. **真渲染逐页目检**：文字溢出、元素重叠、被裁切、颜色问题。
2. **全页缩略图体检**（关键）：把 `render` 产出的缩略图网格摊开看，只答两个问题——
   - 哪几页**视觉元素 <20%**（视觉荒漠）→ 返工
   - 有没有**连续 3 页同节奏** → 换**图表形态**打破（横向条 → 垂直柱状/单位格条/点图），**不是换个颜色了事**
3. **在 PowerPoint/WPS 里打开成品**，确认每个元素都能选中编辑（文字是文字、形状是形状）。

> ⚠ **预览自检的代偿陷阱**：只做一端（如只在 HTML 预览里看）**查不出"PPT 端漏画元素"**。唯一可靠方式是把 pptx 真渲染成图亲眼看。本包的 `render` 就是干这个的。

### 11.3 视觉复核的防误报规则

- 报"尺寸不一致 / 文字错字" → **先核对生成源码**再改（等宽循环布局、深底小字识别掉字都属误报）。
- 报"元素缺失 / 重叠 / 裁切" → 可信度高，直接修。
- 判断"某处是不是深色"要**扫像素**，别靠图像描述下结论。

## 12. 环境与依赖（缺什么怎么办）

### 12.1 必需

| 项 | 要求 | 缺了会怎样 |
|---|---|---|
| Python | 3.10+ | 跑不了 |
| python-pptx / Pillow / pypdfium2 | `pip install -r scripts/requirements.txt` | 跑不了 |
| **渲染器**（二选一） | LibreOffice `soffice`（跨平台推荐）或 Windows 上的 WPS | **不能真渲染** → 视觉自检降级 |
| 中文字体 | 微软雅黑（Windows 自带）或思源黑体（开源可商用） | pptx 里字体会回退 → 用户机器上整体重排 |

### 12.2 三条硬要求（做服务/接入时必须满足）

1. **必须异步**。一份 deck 是分钟级——做成"提交任务 → 进度 → 取件"，不要点一下等白屏。
2. **附件必须由服务端接住落盘**。通用 LLM API 的 messages 接口**不接收 Word/Excel/pptx 附件**（会被拒），材料上传只能走自己的服务层。
3. **密钥只在服务端**，客户端只调用。

### 12.3 服务端跑在 Linux 时

**没有微软雅黑授权** → 用开源可商用字体（思源黑体/Noto Sans CJK）并**嵌入 pptx**。
否则"你渲染的效果"和"用户下载后打开的效果"不是一回事——字体回退会导致整体重排。
嵌入方式：`python-pptx` 无原生嵌入 API，需后处理 `ppt/fonts/` 与 `<p:embeddedFontLst>`；或退一步——**在交付说明里明确告知用户所需字体**。

## 13. 已知坑（都已在代码里处理，改代码时别踩回去）

| 坑 | 处理 |
|---|---|
| 中文字体只设 latin → 中文回退 | `primitives.set_run()` 同时写 `a:ea`/`a:cs` |
| 形状默认阴影 → 业余感 | 所有 `rect()` 关 `shadow.inherit` |
| WPS 渲染输出目录有同名 PDF → 不覆盖而是出 `(1).pdf`，后续仍读旧文件 → **自检全废** | `render.to_pdf()` 先清空输出目录 |
| 表格沿用 Office 默认蓝主题 | 清 `tableStyleId` + 关 firstRow/bandRow |
| 三角形默认尖朝上 | `primitives.arrow_right()` 强制 `rotation=90` |
| 全角标点更宽 → 折行变化 | 标点在**写入前**归一化（`compile._normalize_deep`），改完必须重新真渲染复检 |
| `compare` 的 `left/right` 被误判为几何字段 | `schema` 对该块类型豁免 |

**扩展建议**（当前版本没有、需要时再加）：

- **按页拆分 spec** 以实现真正的"只重算一页"（见 §7 注）。
- **模板取皮**：从用户给的 .pptx 里按频次统计出色彩/字体阶梯 + 导出素材（需 XML 解析）。
- **版式加厚**：加一种版式 = 在 `layout.py` 写一个 `_r_xxx()` 并注册，几何全部用 `tokens` 栅格算，**不写魔法数字**。

## 14. 边界：这套能力不做什么

| 不做 | 理由 |
|---|---|
| 图上拖拽改位置/尺寸的真 WYSIWYG 编辑 | 与"对话改稿"是两条冲突路线；引入元素级反向写回会让"预览=导出"的一致性失守 |
| 从模板自动克隆版式 | 准确率不可控、工程量大；版式库自建已能覆盖，形似靠"取皮 + 自建版式"解决 |
| 多人协作 / 审批流 / 权限 / SSO | 与"做 PPT"本身无关，属宿主产品的活 |
| 动画 / 转场 / 音频旁白 | 非汇报刚需，且是渲染一致性风险源 |
| 图表与 Excel 数据联动刷新 | 依赖外部系统，收益低于成本 |
| 非中文场景 | 版式规则（字号下限、全角标点、饱满度）全部为中文场景定制 |

## 15. 验收标准：怎么判断"真的跑通了"

```bash
python scripts/run.py all assets/deck.sample.json -o out.pptx
```

**四项全过才算成功：**

1. 退出码 0（编译 + 质检 + 渲染全通）
2. `qc` 返回 `ok: true`（0 阻断）
3. 打开缩略图网格目检：无溢出、无重叠、无裁切、无视觉荒漠页、无连续 3 页同节奏
4. 在 PowerPoint / WPS 里打开 `out.pptx`，**每个元素都能选中并编辑**

只用"生成了文件"当作成功，是不够的——本包的价值就在第 2、3、4 项。
